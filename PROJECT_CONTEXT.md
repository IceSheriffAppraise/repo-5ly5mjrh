# Food Kitchen — контекст проекта

Проект: Food Kitchen / Level Kitchen style backend.

Ситуация:
Старый проект был сделан в прошлой Devin-сессии, но не был запушен в GitHub из-за ошибки 403. Старый локальный коммит был 4fbd106, ветка devin/1781894698-ui-revamp. Сейчас проект восстанавливается в новом репозитории.

Главное правило:
GitHub — единственный источник кода. После каждого крупного этапа обязательно делать commit и push.

## Цель проекта

Сделать сайт питания с управляемым меню, калькулятором, админкой и заявками.

Это не просто лендинг, а мини-CMS для бизнеса:

- меню управляется из админки;
- калькулятор управляется из Supabase;
- блюда управляются из админки;
- заявки приходят в админку;
- фото блюд загружаются с компьютера или телефона;
- отдельной корзины нет;
- оплаты нет;
- личного кабинета клиента нет.

## Публичный сайт

Нужны блоки:

1. Главный экран.
2. Конструктор рациона / калькулятор.
3. Меню на день.
4. Форма оформления заявки.

## Калькулятор

В калькуляторе должны быть:

- программы: ФИТ, ХИТ, ПРО;
- дата первой доставки;
- калорийность;
- продолжительность: 2, 4, 6, 14, 30 дней;
- на 30 дней плашка «Рассрочка» белым текстом на чёрном фоне;
- переключатель «Без рыбы»;
- выбор формата заказа внутри калькулятора: «Разовый заказ / Подписка»;
- итоговая цена;
- кнопка «Оформить заказ».

Отдельный блок «Оформите подписку на питание» полностью убрать. Подписка должна быть встроена внутрь калькулятора.

## Админка

Нужны разделы:

- /admin/menu — блюда;
- /admin/programs — программы;
- /admin/calculator — тарифы, калории, приёмы, цена;
- /admin/delivery — длительности, скидки, дефолт;
- /admin/orders — заявки;
- /admin/content — тексты сайта.

## Supabase

Supabase должен быть источником данных.

Нужны таблицы:

- dishes;
- programs;
- meal_plans;
- delivery_rules;
- pricing_rules;
- orders;
- bonus_settings;
- site_content.

Нужны миграции и сиды.

RLS:
- публичный пользователь читает только active-данные;
- публичный пользователь может создать заявку;
- заявки нельзя читать публично;
- изменение данных только через серверную часть / админку.

## API

Нужны маршруты:

- /api/config;
- /api/menu;
- /api/programs;
- /api/meal-plans;
- /api/delivery-rules;
- /api/pricing-rules;
- /api/orders;
- /api/upload/dish-image.

## Фото блюд

В админке нельзя оставлять только URL.

Нужно:

- загрузка фото с компьютера;
- загрузка фото с телефона / из галереи;
- input type="file" accept="image/*";
- Supabase Storage bucket dish-images;
- публичное чтение изображений;
- форматы jpg, jpeg, png, webp;
- лимит 5 МБ;
- превью перед сохранением;
- сохранение итогового public URL в dishes.image_url;
- старые URL не ломать.

## Проверки

Перед завершением каждого этапа:

npm run typecheck
npm run lint
npm run build

Если команд ещё нет — добавить стандартные проверки проекта.

Также проверить:

- главная страница открывается;
- калькулятор работает;
- /admin/menu открывается;
- /admin/programs открывается;
- /admin/calculator открывается;
- обновление страницы на /admin/programs не даёт 403/404;
- /api/config отдаёт JSON;
- изменения из админки влияют на сайт.

## Запрещено

Не делать:

- корзину;
- оплату;
- личный кабинет клиента;
- отдельную большую секцию подписки;
- хранение ключевой логики только в коде;
- работу без commit и push.
